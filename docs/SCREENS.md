# 画面一覧

| パス | 認証 | 最小ロール | 説明 |
| --- | --- | --- | --- |
| `/` | 不要 | - | ログイン状態に応じて `/dashboard` または `/login` へリダイレクト |
| `/login` | 不要 | - | ログイン |
| `/signup` | 不要 | - | 新規登録（保護者・運営者共通） |
| `/forgot-password` | 不要 | - | パスワード再設定メール送信 |
| `/reset-password` | 要（リカバリーセッション） | - | 新しいパスワードの設定 |
| `/invite/[token]` | 任意 | - | 招待リンク受諾。未ログイン時はログイン/新規登録へ誘導 |
| `/auth/confirm` | - | - | Supabaseメールリンク（登録確認・パスワードリセット）のRoute Handler |
| `/dashboard` | 必要 | member | 所属スクール一覧（本アプリは単一スクール専用なので実質1件） |
| `/[schoolId]/events` | 必要 | admin \| guardian | イベント一覧。今後の予定を開いた状態で表示し、過去のイベントは件数だけ出して畳む。右上の＋から作成（管理者のみ表示）。保護者にはイベントごとに自分の子どもの回答状況を表示し、未回答が残っていれば件数を告知する |
| `/[schoolId]/events/new` | 必要 | admin | イベント作成。締切も設定できる |
| `/[schoolId]/events/[eventId]/edit` | 必要 | admin | イベント編集。日時・名称・場所・締切を変えると保護者へ通知が飛ぶ。出欠は保持される |
| `/notifications` | 必要 | member | お知らせ一覧。未読はヘッダーのベルにバッジで出る |
| `/[schoolId]/events/[eventId]` | 必要 | admin \| guardian | イベント詳細・出欠入力（管理者は全会員、保護者は自分の子どものみ）。会員1人＝1行、出欠バッジのタップでポップアップ→確認ダイアログ、名前のタップで回答履歴 |
| `/[schoolId]/children` | 必要 | admin \| guardian | 会員1人＝1行、タップで詳細編集を展開。右上の＋は、管理者=保護者への招待リンク発行/コピー・共有、保護者=お子さま登録。2件以上で絞り込み（カテゴリー/クラス、未設定のみ も選べる）と並び替え（登録順/名前順/カテゴリー順/クラス順）を表示。条件は `?category=&class=&sort=` としてURLに持つ |
| `/[schoolId]/settings` | 必要 | admin | カテゴリー・クラスのマスタ管理、招待リンクの発行・一覧・失効 |

## UI方針

- モバイル片手操作を優先（`max-w-sm mx-auto`、大きめのタップ領域）
- 画面間の移動は画面下部固定のボトムメニュー（イベント／会員・お子さま／お知らせ／設定）。
  親指が届き、スクロールしても消えないため。設定は管理者のみ表示し、お知らせには未読バッジを出す。
  単一スクール専用なので、所属スクールを `(protected)/layout.tsx` で解決してメニューに渡している
  （`/notifications` のようなスクール配下でないページでもメニューを出せる）
- Server Actions + `<form action={...}>` を基本とし、クライアントJSは最小限に留める
  （`SubmitButton` の pending 表示と、出欠変更ダイアログ `AttendanceStatusButton` のみ）
- 開閉だけの UI は `<details>/<summary>` を使い、クライアントコンポーネント化しない（回答履歴、会員の編集欄など）
- モーダルはネイティブ `<dialog>` + `showModal()`。Esc・フォーカストラップ・背景暗転が標準で効く
- 一覧は「1行 = 1件」を基本とし、詳細・編集はタップで展開する
- 一覧画面は「見出し＋右上の丸い＋ボタン」で新規作成に統一する（イベント／会員とも同じ位置）
- 管理者は会員(子ども)を直接登録できないため、会員一覧の＋は招待リンクの共有になる
- `navigator.clipboard` / `navigator.share` は権限や環境で使えないことがある。
  失敗時は無反応にせず、テキストを選択状態にして手動コピーへ誘導する
- 出欠のような取り消しづらい変更には確認ダイアログを挟む。誤タップ対策と、
  `attendance_logs` に履歴が残ることの両輪で運用ミスを吸収する
- エラーはリダイレクト先のクエリパラメータ経由で表示し、`lib/errors.ts` のドメイン別コードに従う
